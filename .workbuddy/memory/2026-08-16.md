## 分类点击无数据修复（本轮）

- 现象：前端扩到 11 个分类，但点击「人工智能/编程开发/创业与商业/设计与产品/区块链与加密货币/网络安全/科学」等显示空白。
- 根因：演示数据只覆盖了 4 个旧分类（科技/开源项目/全球新闻/自定义站点），`list_items` 用 `category = ?` 精确匹配，其余分类在库里无对应行 → 返回空。分类词表本身没问题（collectors.py 的 11 个分类与前端完全一致，真实联网采集会正确落库）。
- 修复：写一次性脚本把演示数据重新铺满全部 11 个分类（每类 3~5 条，日期跨度覆盖 week/month/quarter/year 以便时间筛选可见效），并预置 1 条英文原文+中文翻译样例（HN 条目，engine=google）供「原文/中文翻译」Tab 演示、1 条中文原文样例。共 39 条。验证：各空分类现在都返回数据，一周最热=8 条，content 接口 cached=True 且翻译正常。
- 说明：演示数据仅为沙箱无外网时的占位；用户本机联网后「刷新全部」会用真实采集覆盖。

## 原文抓取失败修复（本轮）

- 现象：点开未预置正文的条目时接口抛 502，前端显示「原文抓取失败」。
- 根因：`main.py` 的 `GET /items/{id}/content` 在 `fetch_article` 失败时直接 `raise HTTPException(502)`，而沙箱无外网 → 几乎全部演示条目都触发。
- 修复：
  - `main.py`：抓取失败/返回空时不再报错，回退展示 `summary`（新增 `fallback` / `fallback_reason` 字段）；翻译也加异常保护；**仅当真正抓到原文时才写库缓存**，避免把摘要误存为原文。
  - `App.vue`：`loadContent` 读取 `fallback`/`fallback_reason`，`selectItem` 重置该状态；模板在正文上方用 `.translate-hint` 样式显示降级提示，不再当作错误。
  - 演示数据：重新铺数据并为全部 39 条预填 `content` 正文（按分类生成中文展开句），保留 HN 英文原文+中文翻译样例。现在离线点开每条都能看到完整「原文/翻译」。
- 验证：缓存条目 cached=True；插入无正文+不可达 URL 的临时条目请求接口返回 HTTP 200 + fallback=True + 本地摘要（非 502）；英文样例 cached=True、language=en、engine=google、翻译正常；清理后总条数恢复 39。
- 注意：前端 dev server（5173）曾掉线，已重启；后端(8765)用 venv python 运行中。
